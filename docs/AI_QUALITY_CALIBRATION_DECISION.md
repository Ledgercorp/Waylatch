# V2 calibration decision, before held-out predictions

14 October 2026. Keep the pre-corpus revised scorer unchanged. This is a conservative presentation decision, not a successful duplicate-detection claim. The primary targets fail on calibration and strong-tier precision is undefined because it emits zero strong alerts.

80 new cases in four calibration families; 29 duplicate, 36 distinct, 15 ambiguous. On the same 65 binary pairs and genuine local MiniLM vectors, v1 combined gives TP27/FP35/FN2/TN1 (precision .4355, recall .9310, F1 .5934). Revised attention gives TP8/FP10/FN21/TN26 (precision .4444, recall .2759, F1 .3404). FPR falls from .9722 to .2778 (71.4% relative reduction), but exceeds the predetermined .10 limit and misses .50 recall. Strong TP0/FP0/FN29/TN36; precision undefined and target fails. At the fixed 13-pair budget, duplicates retrieved rise only from 3 to 4 (recall .1034 to .1379). Records-only tier accuracy is 34/72 (.4722); eight ambiguous tiers excluded. This is weak agreement, not tier validation.

Inspecting calibration failures: shared invoice documents/references still create distinct attention alerts (different accessory or product lines, equal-value labour batches and deposits). Rescans, corrections, quote conversions and returns miss attention because their identity facts differ or are missing. Most authored records omit optional amountKind and expenseAt: exactness/time must remain unknown. A better embedding cannot supply missing payment/line-allocation facts. Fourteen records-only annotated strong pairs receive no strong prediction; annotators consider some self-declared reference/amount combinations sufficient, while this scorer requires receipt/reference/exact-amount/expense-time corroboration. This disagreement is preserved.

A calibration-only alternative considered allowing a matching reference and equal numeric amount despite unknown exactness and different receipt files. It raises TP8 to15 and FP10 to17 (FN14/TN19). Seven additional legitimate repeats, subscription periods and reference reuse cases would need attention. The alternative is rejected because it increases the already excessive false-alert burden. [Exact cases and rule](../evaluation/review-quality-v2/calibration-rejected-alternative.json). No receipt-specific, vocabulary-specific or scenario-only exceptions are added. Neither labels nor records are changed to improve these results.

Before calibration, strict schema validation caught one authoring record with amountKind unknown and a numeric amount. The invalid numeric amount was removed, original case and judgments retained, and two fresh blind judgments obtained. No v2 predictions existed at that point. [Repair evidence](../evaluation/review-quality-v2/authoring-schema-repair.json). This correction is unrelated to scoring outcomes. Final 240-case annotations contain 83 duplicate, 116 distinct and 41 ambiguous identities; two raw judgments per case, one identity disagreement and 22 tier disagreements merged to ambiguity. Two superseded repair judgments are also retained.

Proceed to freeze all final scoring sources, settings, model/dependencies, dataset and labels using the separate v2 manifest. Execute held-out once, preserve any unfavorable result and report every predefined target. Do not modify code or create another manifest to rerun after viewing held-out predictions. Original v1 artifacts remain byte-identical. Original 12-case benchmark remains a historical threshold-selected fixture, not independent validation.
