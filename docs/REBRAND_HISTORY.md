## Compatibility decisions

- IndexedDB **rescueledger-field-v1**, version1, `requests`/`receiver` stores, key paths and persisted outbox/receiver layouts remain unchanged. No migration or request deletion.
- **RL1:** transport prefix, envelope version, request IDs, field names, budgets, CRC32 and fragment/revision semantics remain unchanged. Historical literal packets are pinned from the baseline implementation, not regenerated by the new encoder in compatibility tests.
- SQLite default **data/rescueledger.sqlite**, record IDs, payment state machine, API routes and `rl_session` cookie remain unchanged.
- Existing PayPal sender_batch_id, sender_item_id, recipient, PayPal-Request-Id values/keys and procurement references remain unchanged. Only the display email subject changes. No existing financial operation is renamed or replayed.
- Audit event format, canonical serialization, SHA-256 algorithm, stored data and receipt digests are unchanged. A baseline chain containing the literal RescueLedger name validates; rewriting its name fails validation as expected.
- AI model ID/revision/hash manifest and **RESCUELEDGER_MODEL_PATH** compatibility variable remain unchanged.
- Disposable service-worker shell cache upgrades from **rescueledger-shell-v1** to **rescueledger-shell-v2** in the same namespace so the old title can refresh. Only old shell caches are removed; IndexedDB, financial SQLite and audit storage are unaffected. New manifest/icon are available offline after warmup.
